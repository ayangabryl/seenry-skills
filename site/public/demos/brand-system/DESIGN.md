# Seenry library example

Follow [BRAND.md](BRAND.md), version 1, for shared identity, component and behavior rules. Read it before extending either view. The token/component implementation paths are relative to the repository root.

This example demonstrates what Seenry Branding should deliver: project-owned rules tied to source code, plus multiple screens that apply them. A reference screenshot alone is research, not the deliverable.

Library and Saved share the same row, button, font roles, search and saved IDs. The Guidelines tab explains that contract; the full document is linked above. No separate palette, screenshot-based screen or real backend is involved. No scope exceptions are currently needed.

Verification: saving Architecture in Library persists into Saved; search with no matching record has a recovery message; both views and the guideline tab render at desktop and 390px viewport width; no mobile horizontal overflow. Shared component behavior is implemented, not represented by screenshots.
