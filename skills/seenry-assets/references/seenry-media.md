# Use Seenry media for the current decision

The optional MCP supplies reference evidence and serving URLs from the Seenry CDN. Start with the connected tool schemas and the selected item's metadata. The library is not an approved stock-asset pack or an automatic aesthetic judge.

## Retrieve a useful slice

1. Name the unresolved relationship: opening composition, product evidence, type density, selection feedback, page rhythm or another concrete choice. Search that need and the relevant platform. Prefer a small varied shortlist; a high rating without task fit is insufficient.
2. Follow each result's returned detail tool and arguments. Website pages use `get_page` then `get_screenshot`; recordings use `get_page_motion`. Ordered collections use `get_design_reference` then `get_reference_asset`. Creator clips use `get_design_video`. Retrieve summaries before full media.
3. Keep the returned ID, source/reference link, capture date, viewport, theme, dimensions, media URL and warnings. Use the exact serving URL; do not guess CDN keys or collect unrelated assets. Resolve expired/unavailable links through the item tool again. A URL listing is not an inspection.
4. Inspect the relevant pixels or playback. For a full hero, check its lower visual and responsive counterpart. For video, watch normal speed, then sample frames only when a specific timing or continuity question needs diagnosis. A poster cannot prove motion.
5. Record the relationship to transfer and what must differ for the project's audience, content and identity. Preserve these decisions in DESIGN.md; keep a small provenance record rather than repeatedly loading the media library.

## Separate reference evidence from deliverable assets

A screenshot can support analysis or a reference comparison without becoming an image in the shipped interface. Fonts and artwork depicted inside a screenshot are not independently supplied or licensed by that capture. Do not present a source UI screenshot as a newly implemented product.

If a returned asset is appropriate and permitted for the intended delivery, store it through the host's supported asset workflow, record its source and rights, and provide intrinsic dimensions, responsive crops and loading fallback. Confirm the selected URL returns the expected media type and inspect it in the actual layout. Do not hotlink a reference merely because it is on Seenry's CDN.

For missing illustration or photography, use an available image-generation skill/tool when useful. Specify subject, material, composition, crop and transparent background when required. Inspect the generated result at its rendered size; reject weak outputs instead of calling them premium because generation succeeded. Keep text, controls and live product UI in code. Use genuine permitted identity assets. Disclose generated approximations in reference-recreation work.

## Originality and fallback

For original work, transfer relationships rather than a recognizable combination of someone else's logo, copy, artwork and composition. A deliberate reference recreation follows the user's specified fidelity instead. More references do not mean a better output: stop when the current choice has enough evidence, then build and compare a finished slice.

Without MCP, use supplied media, ordinary permitted browsing or the local craft modules and technical examples. Preserve the same functional, visual and responsive review. Mark evidence gaps honestly; do not manufacture external approval or replace missing judgment with an arbitrary confidence percentage.
