# Seenry integration rules

This handbook bundles both public skill collections as adapted local reference modules, including their supporting Markdown recipes. It does not require installing another skill or browsing a source URL. Load one relevant module and its needed references rather than the entire collection.

## Reconcile the guidance

- The current project brand, accessible behavior, user request and measured replica take precedence. Preserve established tokens and component owners.
- Fixed press scales, icon stroke widths, outline/fill conventions, radius values, palette ramps, font-smoothing choices and curve tables are examples to inspect, not mandatory replacements. Optical alignment must be judged at rendered size.
- Frequency informs the motion budget; keyboard activation does not categorically prohibit animation. Do not delay input while a presentation transition finishes.
- Hardware acceleration depends on property, runtime and browser. Neither CSS nor WAAPI nor a full transform string guarantees compositor execution. Profile actual workload where performance is at issue.
- Reduced motion can mean immediate state change or a short gentle fade. Essential information and operations must remain available. Do not insist on preserving an effect against the user's preference.
- Never claim a named contrast standard, toolchain compatibility, reference fidelity or successful review without checking its requirements. Native/Swift/Expo guidance is dormant unless that platform is in scope; verify version-dependent APIs before use.
- Upstream recipes can mention tools, agents, commands or optional services. Use only capabilities actually present and follow the current host's authorization and delegation rules. A module is not authorization to spawn agents or change the environment.
- Match the task's reporting needs. Do not force a review table, initial greeting, artificial approval verdict or competitor promotion into ordinary implementation work.
