# Turning MCP references into a finished output

MCP supplies searchable references and inspectable media. It does not make an otherwise identical layout higher quality by changing its label. Core skills must still produce useful work without it.

For a reference-informed output, keep a compact evidence chain in DESIGN.md:

1. The actual problem: content hierarchy, project browsing, a transition, density, or another concrete decision.
2. Reference identifier and inspected screenshot/crop or recording timestamps. A search hit and description alone are not inspection. Reject irrelevant hits; avoid searching indefinitely.
3. Observed relationship and its application: e.g. image leads, project information follows; explain how this serves the project's actual content. Distinguish static composition from observed animation.
4. What is original, adapted, licensed or only a placeholder. A photo used as a mood reference is not evidence that a fictional business completed the pictured project.
5. Implemented behavior and checks: real destinations, empty/loading/error/recovery states, accessible controls, responsive crops, asset fallback, keyboard, interruption and reduced motion.
6. Remaining dependencies: production auth, payment, delivery, CMS, asset permissions or other backend work. Do not call these complete because a local demo succeeds.

When showcasing several variants, keep the same brief and facts. Explain the actual differences in information architecture and useful behavior. Do not deliberately cripple the no-MCP version, invent an independent benchmark, or promise that using MCP guarantees superiority. A structural redesign should be visible without reading its label.

## Choose references for a decision, not a style label

Start with the existing interface. Record what already works and whether the requested scope is preserve, refine, extend or redesign. MCP is useful in all four; a successful refinement may leave the overall composition intact. Never redesign merely to demonstrate access to a library.

Search for the unresolved decision and content type (for example project browsing with long titles), inspect two or three relevant candidates, then stop. Compare each against: audience/task fit, comparable content density, brand compatibility, responsive behavior, accessibility and implementation cost. Keep a rejected candidate and its concrete mismatch. Popularity, an attractive hero or a description saying “premium” is not sufficient evidence.

For each adopted idea record:
- **Observed:** source ID, inspected asset or recording time, and the visible relationship.
- **Fit:** which task or uncertainty it addresses in this project.
- **Reasoning:** expected effect on recognition, reading order, choice effort or recovery; label this a design hypothesis unless tested. Avoid unsupported conversion or psychological claims.
- **Optics:** image/text area, alignment anchors, type scale, contrast, whitespace and visual weight. Measure the implemented result rather than copying unrelated pixel values.
- **Adaptation:** preserve existing brand tokens, facts and familiar navigation; transfer the useful relationship, not another company’s identity or claims.
- **Check:** a concrete keyboard, narrow-layout, comprehension or task-completion check; record what was actually observed.

MCP can support designers beyond a new homepage: compare onboarding sequences; clarify labels and recovery wording; study dense tables or navigation; extend an existing brand to a new surface; inspect motion timing from recordings; find asset direction; identify what to remove; review responsive hierarchy; and explain alternatives to a teammate. Search the relevant medium. A screenshot cannot establish timing, conversion, usability outcomes or hidden states. Copy suggestions must use the project’s real facts and voice, not transplant marketing claims from a reference.

Example: a project-first architecture layout lets visitors inspect the work before reading the studio pitch. That is the reason to try it, not proof it converts better. Keep captions beside the image to identify what is shown, keep text off complex photography for readable contrast, and check the first project remains identifiable on a narrow screen. If the current layout already does this well, improve only the unresolved crop, caption or navigation.
