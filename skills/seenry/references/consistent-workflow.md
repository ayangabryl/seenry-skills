# A consistent workflow with deliberate options

1. **Lock the brief.** Record the user task, facts and rejected treatments. Load the existing DESIGN.md brand and component owners. Keep the same brief when comparing outputs; extra features do not prove higher craft.
2. **Choose the decision.** Layout, content hierarchy, asset direction, control behavior or motion? Improve the named decision without gratuitous rebranding. State what would count as a visible improvement.
3. **Choose a mode.** Replication follows observed geometry and timelines; refinement repairs the existing surface; creation compares genuinely different structures. Do not force three directions into a replication task.
4. **Explore relevant options.** For creation, compare a small number of distinct structures using the same facts. For motion, consider opacity/translation, shared geometry, focus/blur and a fluid surface only where they help. Record why the selected mechanism fits; more effects are not inherently better.
5. **Finish a representative slice.** Build the component in its actual surrounding layout with hover, focus, pressed/open and return states. Use shared token/component owners. Compare with the inspected reference at the same scale. Generic clean endpoints do not prove quality between states.
6. **Transfer, then test.** Carry the system to a second applicable context, checking constraints instead of copying CSS blindly. For fluid rendering, use the motion skill's surface-effects guide: a single connected mass shares one fill. Verify rapid reversal, keyboard, narrow layout and reduced motion.
7. **Publish with evidence.** State what is implemented, what was observed and what remains unverified. A reference link alone is not research; a simulated action is not a production backend. Preserve the user's rejected treatments in the record so the next pass does not repeat them.

Do not turn this workflow into visible explanatory clutter. The output itself must demonstrate the decisions. Avoid adding forms, decorative labels or additional sections merely to showcase a capability the page does not need.
