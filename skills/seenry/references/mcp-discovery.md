# Discover the right evidence with MCP

Read the live `get_library_guide` and exposed tool schemas first. The bundled `mcp-tools.json` is a versioned fallback, not authority over a newer connected server. Do not invent endpoints or parameters.

For an open-ended brief, use `discover_references` for a bounded cross-family starting point. Use short observed terms; omit q for a diverse catalog starting point. This is lexical discovery, not semantic ranking or a beauty score. Inspect candidates before calling them suitable. A broad query returning zero does not establish that the library lacks suitable designs.

## Route by evidence needed

- Websites: `search_references`, then `get_page` and the relevant screenshot/section tools from the live schema.
- Sections: `search_sections`; inspect actual pixels, including section boundaries.
- Apps: `search_designs` with family apps, `search_app_screens`, then `get_app_flow` for ordered journeys.
- Branding and decks: `search_designs` with the corresponding family, `get_design_reference`, then `get_reference_asset`. Preserve slide order and attribution.
- Website behavior: `get_page_motion`. Creator motion inspiration: family motion and `get_design_video`. Static screenshots do not prove motion.
- Vocabulary: `get_library_facets` and `get_design_taxonomy`. Source CSS evidence: `get_tokens`; observed documentation: `get_design`. Editorial candidates: `search_curated_references`. Decision guidance: `get_design_research`.

Read exact schemas before invocation. Follow returned cursors only as far as the brief needs, reuse inspected evidence, and respect credits. Prefer a few complementary references over bulk catalog retrieval.

## Sparse metadata is not absence

Imported collections and native captures have different evidence coverage. Search by product/domain, page name and observed section labels as well as metadata facets. If a restrictive facet yields little, remove it and inspect a broader shortlist. Never invent fonts, industries, interactions, quality ratings or semantic tags to fill gaps. Distinguish an observed label from your interpretation of the pixels. A native capture with sparse tags can still be the best reference for the brief.

## Checks

An unspecified brief should produce candidates from relevant families and a justified narrowing decision. A named app/site should rank exact identity matches ahead of incidental text. A failed group must be reported as unavailable, not as zero catalog coverage. Expiring signed media are inspection links, never permanent landing assets.
