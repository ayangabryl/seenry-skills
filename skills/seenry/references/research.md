# Discover the right evidence with MCP

For a new visual direction with Seenry MCP connected, read the live `get_library_guide` and exposed tool schemas before styling. The bundled `mcp-tools.json` is a versioned fallback, not authority over a newer connected server. Do not invent endpoints or parameters. A narrow repair in an established system only needs new reference research if the defect requires it.

For an open-ended brief, use `discover_references` for a bounded cross-family starting point. Use short observed terms; omit q for a diverse catalog starting point. This is lexical discovery, not semantic ranking or a beauty score. Inspect candidates before calling them suitable. A broad query returning zero does not establish that the library lacks suitable designs.

## Research a concrete brief

When the live server exposes `research_design_brief`, use it for a design decision that needs several search angles and inspected source context. Supply the actual brief, a relevant family, up to three short structural or source queries, and the constraints that decide fit. Keep each query focused: “onboarding”, “interests”, and a named app can test different angles; the server does not infer semantic intent from the full brief. Prefer one or two complementary references. Its 10-credit price includes internal search and context reads; reuse the returned evidence.

Read `selectionBasis`, query match evidence, coverage and gaps. Retrieval order is not proof of visual quality. Inspect the supplied pixels; choose the reference whose content hierarchy and behavior fit the task. If no candidate fits, name the missing relationship and run one more focused search rather than copying an irrelevant famous brand. For ordinary app lookup, ranked `search_app_screens` discloses aliases and interleaves apps; exact mode retains literal search. Use `search_mode: "explore"` when several concepts need exploratory coverage, then read matched and missing terms before accepting a partial hit. Specific failure states such as an incorrect password should not be replaced by a generic sign-in or invalid-email screen. Preserve explicit app, flow, site and page-type filters; constraints written in a brief are not automatically verified by the server.

For a selected hit, `get_reference_context` assembles selected pixels, surrounding flow/page-part evidence, available motion and bounded DESIGN.md. Use `document_focus` or `get_design` with `focus` for a specific evidence question. Focused excerpts preserve source offsets and expose unmatched terms. A missing text match does not mean the visible design lacks that feature. Follow explicit part continuations before treating a truncated page as complete. Use `token_query` when only a captured CSS family such as radius or spacing matters; distinguish matched variables from the total captured set. A missing token match is not a measured absence. For branding and decks, `assetOutline` identifies nearby published slides/assets and their inspection calls. Read the relevant pages before claiming a brand rule or narrative role; the cover alone cannot establish either.

Record the adopted relationship, source ID and inspected evidence, the project constraint it resolves, the adaptation, an alternative and a verification state. For color, justify identity/hierarchy/state and actual contrast; do not invent color psychology. For spacing, name the shared alignment owner and grouping relationship; distinguish measured values from estimates. For layout, explain the reading or action order with real content and narrow reflow. For motion, distinguish recorded behavior from proposed focus/error/touch states. Keep this reasoning in DESIGN.md, not visitor-facing product copy. A neat screenshot, a passing test or a model's self-awarded score cannot certify design quality.

## Accept, narrow or reject

For each inspected candidate, make a brief task-fit judgment: **use** for the relationship directly supported by the source; **partial** for a useful fragment with a named gap; **reject** when the essential state or task differs. Do not accept a whole screen because one part looks appealing. For example, a saved-items empty state may demonstrate grouping but not how the user creates the first item. An invalid-email message cannot demonstrate recovery from a wrong password. `get_design_research` with `topic: "synthesis"` provides worked source-backed judgments when this distinction is unclear.

Use `queryEvidence` to trace which search found a candidate, and `selectionBasis` to understand retrieval order. Inspect complementary sources instead of treating two pages from one company as two independent design directions. When a constraint remains unassessed, resolve it in the source if available or test the proposed implementation; do not mark it verified from metadata.

## Route by evidence needed

- Websites: `search_references`, then `get_page` and the relevant screenshot/section tools from the live schema.
- Sections: `search_sections`; inspect actual pixels, including section boundaries.
- Apps: `search_app_screens` for a state, `search_app_flows` for a named journey across apps, then the returned `get_app_flow` call for its ordered captures. A flow label and source order do not prove that every transition or branch was recorded. Use `search_designs` with family apps for collection lookup.
- Branding and decks: `search_designs` with the corresponding family, `get_design_reference`, then `get_reference_asset`. Preserve slide order and attribution.
- Website behavior: `get_page_motion`. Creator motion inspiration: family motion and `get_design_video`; product films and launch videos are directed with [seenry-video](../../seenry-video/SKILL.md). Static screenshots do not prove motion.
- Vocabulary: `get_library_facets` and `get_design_taxonomy`. Source CSS evidence: `get_tokens`; shared ranges across 2 to 8 captured pages (headline, body, radius, button padding with page counts and outliers): `compare_measurements`; observed documentation: `get_design`. Editorial candidates: `search_curated_references`. Decision guidance: `get_design_research`.

Read exact schemas before invocation. Follow returned cursors only as far as the brief needs, reuse inspected evidence, and respect credits. Prefer a few complementary references over bulk catalog retrieval.

## Sparse metadata is not absence

Imported collections and native captures have different evidence coverage. Search by product/domain, page name and observed section labels as well as metadata facets. If a restrictive facet yields little, remove it and inspect a broader shortlist. Never invent fonts, industries, interactions, quality ratings or semantic tags to fill gaps. Distinguish an observed label from your interpretation of the pixels. A native capture with sparse tags can still be the best reference for the brief.

## Checks

An unspecified brief should produce candidates from relevant families and a justified narrowing decision. A named app/site should rank exact identity matches ahead of incidental text. A failed group must be reported as unavailable, not as zero catalog coverage. Expiring signed media are inspection links, never permanent landing assets.

## Scripted research

`research.mjs` uses the canonical https://mcp.seenry.design Streamable HTTP endpoint and initializes the session before tool calls. It requires an actual brief for paid research; the default bounded plan is free credits, guide (1), brief research (10). It never retries auth/quota/tool errors or converts them into empty results. No script key produces a manual, unresearched handoff. Use connected MCP when available. Old `research/bar` images are not generated automatically; explicitly inspect and select task-relevant craft targets in `.seenry/refs`.
