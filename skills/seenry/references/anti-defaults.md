# Replace defaults with decisions

Use for new websites, a rejected visual direction, or work described as generic/AI slop. This diagnoses the result, not its authorship. Read the existing brief and the user's rejected treatments before choosing a composition. Do not make a generic result appear successful by adding process documentation.

## Before the first styled slice

Write the page's useful facts in ordinary prose. Identify the artifact the visitor came to see: actual work, product state, document, comparison or service evidence. Start the composition with that material and the next useful action. Do not automatically surround it with an eyebrow, slogan, explanatory subtitle, badges and a row of three cards.

For each proposed text layer or ornament, name the information it adds. A studio's location can help someone choose a local practice; a line before that location does not add location information. If the user has rejected that treatment, remove the decoration and put the useful fact where it answers a question. Do not move the same ornament into the footer or rename its CSS class.

Check the whole composition, not a blacklist of ingredients:
- Can the brand name be swapped for an unrelated offering while everything else remains plausible? Replace the subject-independent evidence or structure, not merely the font.
- Does the page repeatedly announce what the next section will already show? Remove duplicate introductions and let useful content begin.
- Is an identity being expressed through the actual subject, or only through cream, a serif, a line and editorial numbering? Compare a composition using the subject's real material.
- Does a diagram establish a useful relationship, or impersonate project evidence? Label conceptual work and source suitable material when the brief permits it.

Uppercase, rules, cards and neutral palettes remain valid when they have a task or established identity role. The current Seenry showcase specifically rejects decorative eyebrows, slash labels and divider lines; preserve that local constraint without exporting it as a rule for every client's work.

## Inspect, subtract, compare

Render the same first slice with and without the suspected decoration. Keep facts, viewport and interactions fixed. Record what became easier or harder to understand. Then inspect full-page rhythm: an attractive opening does not excuse repetitive lower sections.

Read [copy decisions](copy-decisions.md) when text is part of the rejection, and [color combinations](color-combinations.md) when the palette feels arbitrary or too narrow. Contrast tests and clean DOM checks are necessary engineering evidence; they do not settle taste or prove distinction.

A user-rejected generated example remains a failed or unresolved example until the actual replacement is reviewed. Preserve original benchmark outputs; label revisions and human assistance. Never market a repaired artifact as an untouched model run.
