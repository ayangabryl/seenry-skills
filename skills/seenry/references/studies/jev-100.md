# What a 100-request development run exposed

Scope: optional Jev decision routing for website work, not a visual benchmark. Recorded at `evals/jev-100` in the source repository.100 live requests:60 authored routing cases (20 cases ×3 forms),30 context-dependent design choices and 10 follow-ups. Three complete same-content website alternatives were rendered. Subsequent user feedback rejected the selected design as not close to Seenry MCP hero quality. The selected page is rejected, and reference parity was never established. The other variants have no recorded human acceptance.

Exact match to author-defined routing labels was 50/60; base 17/20, reordered 16/20, guided 17/20.19/20 choices were stable under reversal. These small development counts are not a calibrated accuracy estimate. One materially wrong reversal retained a fictional demo's false submission-success message. Known UI/network facts should gate truthful feedback before any model preference is considered.

Other mismatches reveal evaluation design issues: observe and none overlapped when the task was missing; a static-preview concern lacked a clearly observed failure, making compare/repair/observe labels contestable. Define the stage and decision boundary before testing. If observe is an offered action, none should mean no offered action fits, not a second label for missing evidence. Preserve original expectations and results; later clarified probes are diagnostic, not replacement scores.

The page-level choices also varied by task. After actual browser measurements, split suited seeing product and complete opening together, compact suited larger readable evidence, and near-identical mobile variants justified abstention. Independent local winners do not automatically form one coherent page. Hold content/assets fixed, inspect the complete composition, and keep alternatives when the task does not distinguish them.

Use Jev for bounded semantic choices after factual requirements are settled. Preserve failures, inspect rendered outcomes and require fresh-brief visual evidence before changing shared aesthetic defaults. A larger call count improves neither screenshots nor weights by itself.

## Visual rejection after the run

The user said: “this deisng is not even close to heros from seenry mcps screen hero.” The selected furniture-preview composition must not be used as a positive taste calibration or accepted design example. Routing counts and functional checks remain historical observations only.

The run explored three arrangements of the same visual premise, with no direct, readable candidate-to-reference comparison establishing the requested craft standard. That is an execution/evidence gap. It does not establish that furniture imagery, split heroes, lavender or any individual font is intrinsically poor. A new direction must revisit the organising idea and material before refining the same premise again. The proposed workflow correction is unvalidated on fresh briefs; do not call this rejection evidence of skill improvement.
