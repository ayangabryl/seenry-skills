# Research and clean-room notes

Research used the Seenry MCP: `search_sections`, `search_curated_references`, `search_designs(family="motion")`, and `get_design_video`. Search terms and returned candidates are retained in `.seenry/research/results.json`. Additional targeted searches found stronger product examples than the initial lexical matches. No website or transitions-library implementation code was fetched, opened or copied. No reference media is embedded in the gallery.

Search results are not visual proof. We rejected unrelated launch videos (e.g. “Modal” the company, skeleton hardware, and streaming television) and did not use their captions as evidence. The paired reference table below records concrete visual cues from real products and creator explorations. Where the available examples are adjacent patterns rather than exact implementations, that limitation is explicit. It would be inaccurate to claim 2–3 exact recorded implementations for all 28 requested behaviors.

The gallery is an original implementation, not a measured reconstruction. Durations, curves, keyboard semantics, interruption logic and reduced-motion policy come from the brief and Seenry Motion. Static posters establish composition and endpoints only. Luma, Vercel and Queue recordings were downloaded and sampled at multiple timestamps; sampled frames are not evidence of precise source easing or browser performance. A contact sheet of 20 shortlisted visual references was inspected, alongside the three downloaded recordings' sampled frames.

## Component brief and state graph

Audience: agents integrating product UI. Job: make an actual application state change easy to understand with two copyable files. Owned detail: every motion study can be compared in adjacent light/dark contexts.

- Data: initial → changed → changed again; latest actual value wins immediately. Digit animation is presentation only.
- Layers: closed → opening → open → closing → opening; native semantic state changes at activation. CSS transitions retarget current presentation.
- Async actions: ready → pending → success or error; runtime never invents the outcome. Gallery timers are explicitly demonstrations.
- Disclosure: collapsed ↔ expanded; old shell and sibling geometry are captured, new text is painted unscaled, then shell transforms settle.
- Controls: off ↔ on; native input/pressed state commits immediately. Disabled remains inert.
- Stream: idle → receiving → complete or interrupted. Only newly received text fades; no arbitrary token generation.
- Gesture: pressed → dragging → dismissed or returned. Pointer cancellation returns the notice; button dismissal offers a non-gesture path.

The anchor is always the input, current label, selected tab or owning trigger. Controls keep 44px targets. Frequent motion is 150ms; occasional layers 200ms and 150ms exits. Long content wraps, error messages persist, and semantic state never depends on animation completing.
