# Seenry Polish

Inspect the actual screen and project system before changing a component. Preserve its identity and behavior. Work at the component's real footprint; an oversized showcase can make weak proportions look resolved.

## Inspect one family

Choose the related controls or surfaces in scope. Compare baseline, icon weight, hit area, label length, border thickness, corner geometry, fill and focus treatment across normal, hover, selected, disabled, loading and error states. Look for arbitrary changes in a shared role. A separator should end on an alignment anchor; a nested corner should look concentric at its actual padding. Use a real licensed icon or an authored vector when a symbol's silhouette matters. A Unicode placeholder is not automatically an icon system.

Before adding a badge, shadow, rule or motion, identify what it communicates. Compare deletion first when the element duplicates information. Preserve meaningful state and focus even in a quieter variant. A stronger texture or animation cannot repair unclear product evidence, broken copy or the wrong layout. Route those problems back to the owning decision.

Exercise the control by pointer, keyboard and touch where applicable. Check rapid repeat, reversal, interruption, reduced motion and narrow layout. Inspect the result in the host page, not only in isolation. Record the observed defect, the smallest repair and the rechecked state. In a full Seenry installation, use [component finish](../seenry/references/component-finish.md), [controls](../seenry/references/craft/controls.md) and [motion](../seenry-motion/SKILL.md) when behavior over time is central.
