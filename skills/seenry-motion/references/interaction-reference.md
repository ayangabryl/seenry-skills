# Interaction component reference

Use for interaction-led components that need a concrete construction reference. This study includes a [local source snapshot](interaction-source/README.md) of 190 third-party examples, inspected on 2026-09-26. The segmented control was also inspected live at rest and after selection. The source makes mechanisms available offline; it does not prove that Seenry can reproduce every example. For a specific recreation, inspect the user-provided reference's live states and compare the output. The copied code is [MIT-licensed](interaction-source/LICENSE); preserve its copyright and license notice when copying substantial code or styles.

## Choose the fidelity target

- **Recreate a named component:** identify its corresponding local source file and lock the user's reference state. In a compatible React/Motion/Tailwind project, adapting the licensed component, its tokens and relevant helper is often more faithful than rebuilding from a description. Inspect its props, phase state, CSS utilities, SVG geometry, custom hooks and the shared [global tokens](interaction-source/src/app/globals.css). Carry the MIT notice with copied material. In another stack, port the mechanism and compare rendered states; similar CSS alone will not preserve the interaction.
- **Create an original component at this quality level:** study one or two examples with a similar input or object, then design a different response for the user's task. Transfer the construction principles and verification bar, not the reference's exact monochrome skin, copy, object or motion. A production UI may need a quieter treatment than a lab experiment.

The shared stylesheet mostly defines light/dark role tokens and a few site-wide affordances. The distinctive behavior usually lives in each `.tsx` file through Motion values, CSS transitions or keyframes, SVG, and sometimes Canvas or `requestAnimationFrame`. Cloning only `globals.css` will not reproduce it. Treat example-specific choices as reference data, not universal Seenry defaults.

| [Sortable grid](interaction-source/src/lab/components/sortable-grid.tsx) | Stable item IDs and DOM nodes occupy measured slots. Pointer movement updates Motion values directly; neighbors spring to new slots. Drop springs inherit release velocity. Touch uses a hold threshold; keyboard lift/move/drop has announcements. | A click remains a click, an active tile stays above neighbors until landing, rapid reorder keeps focus and identity, touch scroll remains usable, and keyboard reaches the same order. |
| [Odometer](interaction-source/src/lab/components/odometer.tsx) | Each place retains an unwrapped turn count. Ten glyph nodes circulate through modular offsets, so 9→0 rolls forward instead of spinning backward. Velocity controls slight blur; a separate output owns accessible text. | Test 9→10, 99→100, reverse and rapid updates; digits move independently while the overall readout and semantic value remain stable. |
| [Word rotator](interaction-source/src/lab/components/word-rotator.tsx) | A longest-common-subsequence match preserves shared letter IDs. Before/after measurements let retained letters glide to new positions, while entering and exiting letters use separate layers. Container width animates as layout width, not text scale. | Shared letters visibly survive, the sentence reflows without a snap, outgoing letters clear before the glide settles, and a new swap can start mid-transition. |
| [Receipt printer](interaction-source/src/lab/components/receipt-printer.tsx) | Explicit idle/printing/printed/torn phases, line-height-derived feed distances, a clipped paper stage, serrated edge geometry and separate drag-to-tear logic make the object coherent. | Text emerges from the slot only as paper feeds; paper has a consistent material in both themes; the tear responds to pull/twist and leaves a believable stub. |

## Reproduce the craft, not only the endpoint

1. Record the source object's rest frame, input trajectory, active silhouette, release, settled state and return. Inspect hover, focus, keyboard and touch separately where available. Measure the demo's **component** bounds rather than copying its surrounding lab page.
2. Build the smallest runnable slice at the same physical size. Keep semantic state and input mapping separate from visual overshoot, clip or particle layers. Preserve stable hit targets and a single animation owner for each property. For physical objects, geometry, material, occlusion and gesture must tell the same story.
3. Compare source and output at matched size and matched **relative time after input**. Judge the anchor, moving boundary, label/icon timing, material, neighboring movement and exit independently. Use normal-speed playback as well as intermediate frames. A matching resting screenshot or copied easing string does not pass.
4. Exercise rapid reentry, reversal, a narrow viewport, keyboard/touch, dark/light themes where the target has them, live reduced motion, unmount and failed device/async states where relevant. Repair observed gaps and retain the comparison. If these states were not inspected, report the match as unverified.

Some source details are demo-specific tradeoffs. For example, a transition event used to finish a lab hold action may need an independent timer or operation state in production; a showcased sheet still needs the target app's full modal focus behavior. Preserve the observed visual relationship while fixing such correctness gaps. Do not report source availability, an implementation that runs, and inspected fidelity as the same result.
