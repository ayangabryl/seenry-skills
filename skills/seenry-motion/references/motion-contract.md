# A compact motion contract

Write this beside the chosen layout before implementing its important transition. Use the application's real states; an effect name does not establish a product capability. A short control can use one compact record, while a scroll story may use a beat table.

| Decision | Record |
| --- | --- |
| Trigger and state | Pointer, keyboard, touch, scroll or async event; the real state owner; initial and settled states. |
| Anchor and change | What remains stationary, what changes identity or geometry, and why that helps the task. |
| Immediate feedback | How input is acknowledged without waiting for decoration or inventing success. |
| Interruption | What repeated input, reversal, cancellation or a newer result should display. |
| Lifecycle | Who starts, pauses, resizes and destroys the animation, including offscreen behavior. |
| Reduced motion | The usable final state or static sequence, with the same information and actions. |

Keep hit targets, readable text and focus independent of decorative layers. An expanding wrapper may change size without scaling its live typography. Number changes should preserve the unit or separator needed for comparison. A loading indicator follows an actual operation. Report a download as started when dispatched; claim saved only if the host exposes a confirmed save result.

Use one owner per animated property. On interruption, retarget from the displayed state and reject stale async results. Cleanup removes only this interaction's effects and observers. A missing library, failed asset or unavailable GPU must leave a useful interface.

For direct manipulation, render the input value without trailing decorative delay. For scroll, use one seekable progress value with explicit reading holds; the same progress reached in reverse should produce the same presentation. Keep important content reachable through ordinary navigation.

Verify the main transition at normal speed, one interruption, keyboard operation and live reduced motion. Add geometry, resource or lifecycle checks where the chosen mechanism can fail. Preserve failures and unavailable evidence; a screenshot or passing endpoint assertion alone cannot establish smooth motion.
