# Craft integration decisions

This candidate consolidates decisions rather than replacing the existing subject guides.

| Concern | Existing resource retained | New small entry |
| --- | --- | --- |
| Layout and typography | visual-decisions, content-model, type_lab | craft/layout, craft/typography |
| Color | color-decisions, color_lab, palette_study | craft/color |
| Controls and recovery | interaction-review, HCI decisions, interaction_probe | craft/controls |
| Motion | seenry-motion contract/craft, geometry/icon/number/scroll helpers | craft/motion |
| Creative websites | art-direction, asset material guides, worked motion scores | craft/art-direction |
| Feedback | quality-diagnosis, evaluation, review gates | learning-loop |

The small entry is sufficient for a narrow question; deeper resources remain available when their actual decision arises. Existing packet callers can use explicit complete mode for historical expectations. Existing stage recorder contracts and schema remain unchanged.

Resolved overlaps:
- Filled versus outline icons: inspect role and optical weight, not a global default.
- Color: semantic roles and measured pairs coexist with colorful branding; contrast does not select the aesthetic.
- Radius: concentric inset geometry is a starting calculation, not a rule for unrelated controls.
- Motion: exact values belong to the current interaction; frequency, distance, reversal and reduced motion override a copied recipe.
- Variants: compare different structures with equal factual content, not three palette skins. Narrow fixes do not trigger a full exploration.
- Examples: study UI and captions stay outside the product. They demonstrate mechanics and are not branded templates.

The local learning-loop addition is preserved. Published and installed baselines were frozen separately in the development evidence directory. No global installation is updated before acceptance. Upstream notices are included inside the installable skill as well as repository documentation.
