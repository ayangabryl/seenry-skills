# Seat capacity motion trial

An isolated consumer read the published Seenry Motion skill with its new component-first guidance and built an original workshop-capacity control. The fixed brief asked for a 16–28 seat range, 16 confirmed guests, eight waitlisted people, pointer/touch/keyboard input, reset, rapid reversal, reduced motion, and 390/320px layouts. No source component or visual direction was supplied.

The preserved first complete source and wide, 390px and 320px renders put the control and its consequences first, without the oversized editorial wrapper seen in the earlier reorder trial. Fresh independent first-screen typography and whole-screen reviews both returned **Keep** on the initial 16-seat captures. The builder's browser checks found working pointer and keyboard changes, synchronized counts and marks, reset, and no 320/390px overflow. A parent browser check repeated keyboard End/Home/reversal, reset focus, reduced-motion value updates, 320px overflow and console checks. The 320px image saved by the builder is 305px wide because its capture excluded the scrollbar; a separate true-width 320px capture is included. Touch emulation was blocked for the builder, and the parent did not verify a touch gesture or screen-reader behavior.

A second independent full-page review included a focused 28-seat state. It returned **Revise** because the range focus ring crossed the endpoint labels at 320px. This is a first-pass failure in an active state, despite the initial default-state Keep. The parent changed the endpoint-label margin from -2px to 12px, captured focused minimum and maximum states, and a fresh full-page reviewer returned **Keep**. The repair is preserved separately from the first source. The new skill reminder to inspect both focused endpoints was added **after** this trial, so its preventive effect remains untested.

`manifest.json` records artifact hashes and image dimensions. The review summaries include their own input and skill hashes. These results support a narrower observation: the component-first guidance helped on one fresh brief, while the independent state review caught a defect the first render and default-state review missed. They do not prove reliable first-pass quality across components.

A later review-gate prompt correction was tested against these frozen images. With only the first default-state wide and 390px captures, a fresh whole-screen reviewer now returned **Unverified** and named the missing changed-capacity state. With the repaired focused minimum and maximum captures included, another fresh reviewer returned **Keep**. The two `coverage-*-summary.json` files preserve verdicts, input hashes and limits. This tests review coverage, not first-pass prevention or live interaction.
