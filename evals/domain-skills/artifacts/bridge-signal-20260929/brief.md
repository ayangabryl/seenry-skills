# Trial brief: Bridge Signal

Build a small original responsive website for Bridge Signal, a fictional public dashboard that helps people choose when to cross a river footbridge during temporary wind restrictions. This is an independent skill-consumer trial. No existing brand is supplied.

The first screen must answer: Is the bridge open now, when is the next predicted restriction, and what should a walker do? Show the actual decision material there, not only a brand promise.

Supplied facts for the prototype: current sample time 16:20; bridge open now; wind 24 km/h; restriction threshold 35 km/h; forecast 17:00 29 km/h, 17:30 36 km/h, 18:00 38 km/h, 18:30 32 km/h, 19:00 25 km/h. The forecast is illustrative and should not imply live data. The primary action should show the full forecast or jump to it. Include a way to switch between sample conditions, with a meaningful state change, if useful.

The target is a clear, memorable civic interface with credible data hierarchy and thoughtful typography. The user dislikes the generic editorial opening: eyebrow label, oversized soft serif sentence, accent or italic phrase, then atmospheric explanation. Avoid repeating that combined visual treatment. Do not replace it with an equally long generic sans-serif promise stack.
